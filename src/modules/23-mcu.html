A microcontroller puts a processor, memory and peripherals on one chip, and a program controls the hardware by reading and writing the peripherals' registers. Embedded C is mostly ordinary C, plus one essential skill: changing exactly the bits you mean to change in a register, and nothing else. This module uses the ATmega328P, the 8-bit AVR microcontroller on the Arduino Uno, programmed directly through its registers rather than through the Arduino library.

What is in a microcontroller

A microcontroller. Every peripheral is controlled through a handful of memory-mapped registers.

The ATmega328P has an 8-bit AVR core running at 16 MHz on the Uno, 32 KB of flash for the program, 2 KB of SRAM for data, and 1 KB of EEPROM for settings that must survive power-off. Program and data memories are separate (a Harvard architecture), so constant data placed in flash needs special access functions. There is usually no operating system: the program starts at reset and runs forever. It is compiled with avr-gcc into a binary image that a bootloader or programmer writes into flash.

C integer types on an 8-bit machine

C's built-in integer sizes depend on the platform. On AVR, int is only 16 bits (−32,768 to 32,767), so code that assumes 32-bit ints silently overflows. Embedded code therefore uses the fixed-width types from <stdint.h>:

Type | Bits | Range uint8_t | 8 | 0 to 255 int8_t | 8 | −128 to 127 uint16_t | 16 | 0 to 65,535 int16_t | 16 | −32,768 to 32,767 uint32_t | 32 | 0 to 4,294,967,295 int32_t | 32 | −2,147,483,648 to 2,147,483,647

Two rules of C arithmetic cause most surprises:

  • Integer promotion: operands smaller than int are converted to int before arithmetic. With uint8_t a = 200, b = 100; the expression a + b is the int 300; only assigning it back to a uint8_t truncates it to 300 − 256 = 44.
  • Constants are int by default: on AVR, 1 << 15 overflows a 16-bit signed int and 1 << 20 is undefined. Write 1UL << 20 (unsigned long, 32 bits) when the result must be wider than 16 bits.

Use char for text and uint8_t/int8_t for small numbers. A character is stored as its ASCII code: '0' is 0x30, so '0' + 7 is the character '7', while sending the number 7 to a display shows an unprintable control character ().

GPIO: the DDR, PORT and PIN registers

The ATmega328P's general-purpose I/O pins are grouped into 8-bit ports B, C and D. Each port has three registers, and bit n of each register controls pin n of that port:

Register | Meaning of bit n DDRx (data direction) | 1 = pin is an output, 0 = input. All bits are 0 after reset, so every pin starts as an input. PORTx | If output: the value driven (1 = high, 0 = low). If input: 1 enables the internal pull-up resistor. PINx | Read: the current logic level on the pin, whether input or output. Writing 1 to a PIN bit toggles the corresponding PORT bit. One pin's circuitry. The input path passes through a Schmitt trigger and a two-flip-flop synchronizer (), so PIN reflects the pin voltage about one clock cycle late. Uno pin labels and port bits. D13, the pin with the onboard LED, is PB5; the analog inputs A0–A5 are PC0–PC5, which also work as ordinary digital pins.

Changing one bit without disturbing the others

A register holds eight independent controls, so assigning a whole value (PORTB = 0x20;) changes all eight pins. To change one bit, read the register, modify the bit with a mask, and write it back. A mask is a constant with 1s in the bit positions of interest, written in hexadecimal (0x20) or built with a shift (1 << 5, which the AVR headers let you write as 1 << PB5).

OR sets bits, AND with the complement clears them, XOR toggles them, and AND isolates them for testing.

The reasoning behind each operation is the identity table of each operator: x | 1 = 1 and x | 0 = x; x & 0 = 0 and x & 1 = x; x ^ 1 = x′ and x ^ 0 = x. The mask's 1 bits select which positions are affected; its 0 bits leave the rest alone. The six recipes cover nearly all GPIO code:

DDRB  |=  (1 << PB4);          // make PB4 an output
DDRB  &= ~(1 << PB4);          // make PB4 an input
PORTB |=  (1 << PB4);          // drive PB4 high (or enable its pull-up if input)
PORTB &= ~(1 << PB4);          // drive PB4 low (or disable its pull-up)
if ((PINB & (1 << PB4)) != 0)  // PB4 reads 1
if ((PINB & (1 << PB4)) == 0)  // PB4 reads 0
PORTB ^=  (1 << PB4);          // toggle PB4

Several bits are handled at once by ORing shifted ones: PORTD |= (1 << 7) | (1 << 2); sets bits 7 and 2. For I/O registers in the low part of the address space, the compiler turns single-bit set and clear operations into the AVR's one-instruction sbi and cbi, which cannot be interrupted halfway ().

Bitwise versus logical operators, and precedence

C has two families of operators that look alike and behave very differently:

  • Bitwise & | ^ ~ operate on each bit position independently and produce a number.
  • Logical && || ! treat any nonzero value as true and produce 0 or 1.

So 1 && 2 is 1 but 1 & 2 is 0; !0x10 is 0 but ~0x10 is 0xEF (and, after promotion to int, nonzero, so if (~x) is true even for x = 1).

Operator precedence is the other trap. From highest to lowest, the relevant groups are: ~ ! (unary), then * / %, + −, shifts << >>, comparisons < > <= >=, equality == !=, then &, ^, |, then &&, ||, and finally assignment. Because == binds more tightly than &, a missing pair of parentheses changes the meaning completely.

The classic GPIO bugs:

  • PORTB &= (1 << 3); keeps bit 3 and clears every other bit. To clear bit 3, the mask must be complemented: &= ~(1 << 3).
  • PORTB |= (0 << 3); does nothing: 0 shifted anywhere is 0. ORing cannot clear bits, and ANDing cannot set them.
  • if (PIND & (1 << 3) == 0) parses as PIND & ((1 << 3) == 0), which is PIND & 0: always false. Parenthesize the AND.
  • if ((PIND & (1 << 3)) == 1) is never true: the masked value is 0 or 8, not 0 or 1. Compare with 0 (!= 0 or == 0).
  • PORTB = (1 << 5); when you meant |= turns off every other output on the port.

Copying a group of bits

A common task is to copy a multi-bit field from one place to another, for example to put a 4-bit value onto four output pins without changing the other four. Because OR can only make 1s and AND can only make 0s, the destination field must be cleared first and then ORed with the new value, after the new value has been shifted into position and masked to that field.

Copying bits 7–5 of PORTC into bits 5–3 of PORTB: shift right by 2, mask with 0x38, clear the field in PORTB, then OR. 
PORTB &= ~0x38;                    // clear PB5..PB3
PORTB |= (PORTC >> 2) & 0x38;      // bring in C7..C5 at positions 5..3

// The general pattern, for a field of width w starting at bit s:
//   mask = ((1 << w) - 1) << s;
//   dest = (dest & ~mask) | ((value << s) & mask);

Doing it in two statements briefly exposes an intermediate value on the pins (the field cleared to 0). When that matters, compute the new value in a variable and write the register once.

Reading a button

A push button is normally wired between the pin and ground with the internal pull-up enabled, so it reads 1 when released and 0 when pressed (). Mechanical contacts do not close cleanly: they bounce, making and breaking contact several times over a few milliseconds.

Contact bounce on press and release. Without debouncing, one press can be counted as several.

The simplest software debouncer waits a few milliseconds after a change and checks again, then waits for the release, so that one press is handled exactly once:

#include 
#include 

int main(void)
{
    DDRB  |= (1 << PB5);                     // LED on PB5 (Uno D13): output
    DDRD  &= ~(1 << PD2);                    // button on PD2: input
    PORTD |= (1 << PD2);                     // with pull-up: reads 0 when pressed

    while (1) {
        if ((PIND & (1 << PD2)) == 0) {      // looks pressed
            _delay_ms(5);                    // let the bounce settle
            if ((PIND & (1 << PD2)) == 0) {  // still pressed: a real press
                PORTB ^= (1 << PB5);         // toggle the LED once
                while ((PIND & (1 << PD2)) == 0) { }   // wait for release
                _delay_ms(5);                // ignore release bounce
            }
        }
    }
}

This works but blocks: while it waits for the release, the program can do nothing else. restructures the same logic as a state machine that never blocks, and replaces busy-wait delays with timers.

Summary

  • On AVR, int is 16 bits; use uint8_t, int16_t, uint32_t and suffixes such as 1UL. Small types are promoted to int before arithmetic.
  • DDRx sets direction (1 = output), PORTx sets the output value or the pull-up, PINx reads the pins.
  • Set: |= mask. Clear: &= ~mask. Toggle: ^= mask. Test: (reg & mask) != 0.
  • Bitwise and logical operators differ; == binds tighter than &, so parenthesize masks.
  • Copy a field: clear the destination field, then OR in the shifted, masked source.
  • Buttons bounce; debounce with a short delay and confirmation, and act once per press.

Write statements that make PD7–PD4 outputs driving 0 and PD3–PD0 inputs with pull-ups, assuming nothing else uses port D.

DDRD = 0xF0; (upper nibble output) and PORTD = 0x0F; (outputs low, pull-ups on the lower nibble). If other code shares the port, use |= and &= with the same masks instead of plain assignment.

What is the value of each expression for x = 0x5A? (a) x | 0x0F (b) x & 0x0F (c) x ^ 0xFF (d) x >> 4 (e) x && 0x0F

(a) 0x5F (b) 0x0A (c) 0xA5 (d) 0x05 (e) 1 (both operands nonzero).

True or false: PORTD &= (3 << 5); clears bits 5 and 6 of PORTD.

False. 3 << 5 = 0x60, so the AND keeps bits 5 and 6 and clears the other six. Clearing bits 5 and 6 needs PORTD &= ~(3 << 5);.

Why is if ((PINC & (1 << 4)) == 1) wrong, and what are two correct ways to write the test?

The masked value is 0 or 16 (0x10), never 1, so the condition is never true. Correct: if ((PINC & (1 << 4)) != 0) or if (PINC & (1 << 4)).

Write one statement that toggles PB0 and PB1 together and one that sets PC2 and clears PC5 in a single write to PORTC.

PORTB ^= (1 << PB0) | (1 << PB1); and PORTC = (PORTC & ~(1 << PC5)) | (1 << PC2);.

After uint8_t x = 200; x = x + 100;, what is x? What type and value does the expression x + 100 have before it is assigned?

x is promoted to int, so x + 100 is an int with value 300. Storing it in a uint8_t keeps the low 8 bits: x = 300 − 256 = 44.

Extract bits 6–4 of PIND as a number from 0 to 7.

(PIND >> 4) & 0x07: shift the field down to bit 0, then mask off the bits above it.

What does the condition if (PIND & 1 << 3 == 0) actually test? Rewrite it to test whether PD3 is 0.

Shift binds tighter than ==, which binds tighter than &: it is PIND & ((1 << 3) == 0) = PIND & 0 = 0, always false. Correct: if ((PIND & (1 << 3)) == 0).

On AVR, what is wrong with uint32_t mask = 1 << 20; and how is it fixed? Why does the same line work on a desktop PC?

The constant 1 is a 16-bit int on AVR, and shifting it by 20 exceeds its width: undefined behavior, typically giving 0. Write 1UL << 20 (or (uint32_t)1 << 20). On a PC, int is 32 bits, so 1 << 20 fits; the bug only appears when the code is ported.

Put the 4-bit value v (0–15) onto PD7–PD4 without disturbing PD3–PD0, in a single write to PORTD.

PORTD = (PORTD & 0x0F) | ((v << 4) & 0xF0);. The AND keeps the low nibble and clears the high one; the shifted, masked value supplies the new high nibble.

Write an expression that is true when exactly one bit of the unsigned value x is 1, and explain why it works.

x != 0 && (x & (x - 1)) == 0. Subtracting 1 clears the lowest set bit and sets all bits below it; ANDing with x therefore clears the lowest set bit. If x had only one set bit, the result is 0. (This is the power-of-two test.)

Count the 1 bits in a byte with a loop that runs once per set bit.

 
uint8_t popcount8(uint8_t x)
{
    uint8_t n = 0;
    while (x) {
        x &= x - 1;   // clear the lowest set bit
        n++;
    }
    return n;
}

It iterates once per 1 bit (Kernighan's method), so 0x81 takes two iterations.

Using the debouncing program in the text, what happens if the button is held down for 3 seconds? How many times does the LED toggle?

It toggles once: after confirming the press it waits in the release loop for the whole 3 seconds, then debounces the release. The cost is that nothing else runs during those 3 seconds.

Show that x ^= y; y ^= x; x ^= y; swaps two variables without a temporary. When does it fail?

Let the originals be a and b. After the first line x = a ⊕ b. Then y = b ⊕ (a ⊕ b) = a. Then x = (a ⊕ b) ⊕ a = b. It fails if x and y are the same object (for example swapping a[i] with a[j] when i = j): the first line sets it to a ⊕ a = 0 and it stays 0. It is also no faster than using a temporary on modern compilers.

Write a macro or inline function that writes a w-bit value into bits s to s + w − 1 of a register, and use it to set bits 5–3 of PORTB to the value 6.

 
static inline uint8_t set_field(uint8_t reg, uint8_t s, uint8_t w, uint8_t value)
{
    uint8_t mask = ((1u << w) - 1u) << s;
    return (uint8_t)((reg & ~mask) | ((value << s) & mask));
}

PORTB = set_field(PORTB, 3, 3, 6);   // bits 5..3 become 110

The mask for s = 3, w = 3 is 0x38; 6 << 3 = 0x30, so bits 5 and 4 become 1 and bit 3 becomes 0.
