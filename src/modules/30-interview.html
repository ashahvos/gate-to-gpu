The problems below are typical of the questions asked in screening tests and technical interviews for digital design, verification, architecture, GPU and embedded positions. They mix quick checks of fundamentals, short design tasks and longer questions with a trap in them. Interviewers usually care less about the final number than about the reasoning: say what you are assuming, name the principle you are applying, and check your answer against a simple case. Convert 615₈ to hexadecimal.

Through binary: 6 1 5 → 110 001 101 → regroup in fours from the right: 1 1000 1101 → 0x18D (= 397). ()

What is the minimum number of bits needed to give 384 different items distinct codes?

2⁸ = 256 < 384 ≤ 512 = 2⁹: 9 bits.

What is the range of an 8-bit two's complement number? What is the result of negating −128 in 8 bits, and why?

Range −128 to +127. Negating −128 (1000 0000) by inverting and adding 1 gives 0111 1111 + 1 = 1000 0000 = −128 again: +128 is not representable, so the negation overflows. ()

Interpret the byte 1001 0011 as an unsigned number, a sign-magnitude number and a two's complement number.

Unsigned: 128 + 16 + 2 + 1 = 147. Sign-magnitude: sign 1, magnitude 001 0011 = 19 → −19. Two's complement: 147 − 256 = −109.

Write a C expression that detects signed overflow in s = a + b for 32-bit ints, computing the sum without undefined behavior.

Compute in unsigned arithmetic, which wraps legally: uint32_t s = (uint32_t)a + (uint32_t)b;. Overflow occurred if a and b have the same sign and s has a different one: ((a ^ s) & (b ^ s)) >> 31 (as unsigned), i.e. the sign bit of (a ⊕ s) AND (b ⊕ s). This is the software form of the hardware rule V = Cn−1 ⊕ Cn. GCC and Clang also offer __builtin_add_overflow.

Multiply an integer x by 7 using only shifts and one addition or subtraction. By 10?

7x = (x << 3) − x. 10x = (x << 3) + (x << 1). Compilers do this automatically when it is cheaper than a multiply.

Encode −0.75 in IEEE 754 single precision (hex).

0.75 = 1.1₂ × 2⁻¹. Sign 1; exponent −1 + 127 = 126 = 0111 1110; fraction 1000…0. Bits: 1 01111110 1000 0000 0000 0000 0000 000 = 0xBF400000. ()

Why does 0.1 + 0.2 == 0.3 evaluate to false in C with doubles? How should floating-point values be compared?

None of the three values is exactly representable in binary (each is a repeating binary fraction), so each is rounded, and the rounded sum of the first two differs from the rounded 0.3 in the last bit (the sum is stored as 0.3000000000000000444…, while 0.3 is stored as 0.2999999999999999888…). Compare with a tolerance appropriate to the magnitudes involved, for example fabs(x − y) <= 1e-12 * fmax(fabs(x), fabs(y)), or restructure the computation to avoid needing equality.

What is the smallest positive integer that cannot be represented exactly in FP32? Why?

FP32 has 24 bits of significand (23 stored plus the hidden 1), so every integer up to 2²⁴ = 16,777,216 is exact. Above that, consecutive representable values are 2 apart, so 16,777,217 is the first that cannot be represented (it rounds to 16,777,216). A float counter incremented by 1 stops growing there.

A 12-bit two's complement value arrives in the low bits of an unsigned 32-bit variable x (upper bits zero). Sign-extend it to a 32-bit signed value without branches.

int32_t v = (int32_t)(x ^ 0x800u) - 0x800;. If bit 11 is 0, the XOR adds 2048 and the subtraction removes it again. If bit 11 is 1, the XOR removes 2048 and subtracting another 2048 yields x − 4096, the correct negative value. The XOR result is between 0 and 4095, so the conversion to int32_t and the signed subtraction are always well defined. The common alternative ((int32_t)(x << 20)) >> 20 relies on implementation-defined behavior: converting an out-of-range unsigned value to a signed type, and right-shifting a negative number.

Write a branchless saturating addition of two uint8_t values (results above 255 clamp to 255).

 
uint8_t sat_add_u8(uint8_t a, uint8_t b)
{
    uint16_t r = (uint16_t)a + b;      // 0..510, the carry lands in bit 8
    r |= -(r >> 8);                    // if bit 8 is set, OR in all ones
    return (uint8_t)r;
}

If the sum is below 256, r >> 8 is 0 and nothing changes. Otherwise it is 1, its negation is all ones, and the low byte becomes 0xFF. Hardware does the same with the carry-out driving a mux. DSP and GPU instruction sets have saturating arithmetic built in.

What is the Gray code of 13, and how is it computed in general?

G = B ⊕ (B >> 1): 1101 ⊕ 0110 = 1011. Consecutive Gray codes differ in exactly one bit, which is why Gray-coded counters are safe to pass between clock domains. ()

Using only 2-to-1 multiplexers (and the constants 0 and 1), build NOT, AND and OR.

A mux computes S′·I0 + S·I1. NOT A: S = A, I0 = 1, I1 = 0. A AND B: S = A, I0 = 0, I1 = B. A OR B: S = A, I0 = B, I1 = 1. Since NOT and AND form a complete set, a 2-to-1 mux is universal. ()

What is the minimum number of 2-input NAND gates needed to build XOR? Sketch the structure.

Four. N1 = (AB)′; N2 = (A·N1)′; N3 = (B·N1)′; Y = (N2·N3)′ = A ⊕ B. The shared first gate is the trick. ()

Build a 4-to-1 mux from 2-to-1 muxes. Then build an 8-to-1 mux from 4-to-1 and 2-to-1 muxes.

4-to-1: two 2-to-1 muxes on S0 select between (I0, I1) and (I2, I3); a third, on S1, selects between their outputs: 3 muxes. 8-to-1: two 4-to-1 muxes on S1S0 handle I0–I3 and I4–I7; a 2-to-1 mux on S2 picks one: 2 + 1.

Implement an arbitrary 3-input function F(A, B, C) with a single 4-to-1 mux and at most one inverter.

Use A and B as the selects. For each of the four (A, B) combinations, F restricted to that combination is a function of C alone, which can only be 0, 1, C or C′; connect that to the corresponding data input (one inverter supplies C′). This is Shannon expansion: F = A′B′·F(0,0,C) + A′B·F(0,1,C) + AB′·F(1,0,C) + AB·F(1,1,C). An FPGA LUT is the same idea taken to all inputs.

Minimize F(A, B, C, D) = Σm(0, 2, 5, 7, 8, 10, 13, 15).

The 1s are all cells with B = D = 0 (the four corners) and all cells with B = D = 1 (the center square): F = B′D′ + BD = (B ⊕ D)′, an XNOR of B and D; A and C are irrelevant. ()

Derive a minimal SOP for A > B, where A = A1A0 and B = B1B0 are 2-bit unsigned numbers.

A > B = A1·B1′ + A1·A0·B0′ + A0·B1′·B0′. The first term is "the high bits decide" (A1 = 1, B1 = 0). The other two cover "the high bits are equal and A0 > B0": A1·A0·B0′ handles A1 = B1 = 1, and A0·B1′·B0′ handles A1 = B1 = 0. Each has dropped one literal by merging with cells the first term already covers, which is why the K-map gives three-literal terms rather than four-literal ones.

Write the equations of a 4-input priority encoder (I3 has the highest priority) with outputs Y1 Y0 and a valid flag V.

Y1 = I3 + I2, Y0 = I3 + I2′·I1, V = I3 + I2 + I1 + I0. Y0 is 1 for index 3 or for index 1, and index 1 wins only if I2 is not active (I3 is already covered by the first term).

F = A·B′ + B·C has a static-1 hazard. When does it glitch, and how is it removed?

With A = C = 1, F should stay 1 when B changes, but as B falls, the B·C term can turn off before the A·B′ term turns on (B′ is delayed by the inverter), giving a brief 0. Adding the consensus term A·C covers the transition and removes the hazard; it is logically redundant. ()

Is {XOR, AND} functionally complete? What if the constant 1 is also available?

Without constants, no: both gates output 0 when all inputs are 0, so every circuit built from them maps all-zeros to 0 and can never produce NOT. With the constant 1, yes: NOT x = x ⊕ 1, and {AND, NOT} is complete. (This basis is the algebraic normal form used in cryptography.)

How many distinct Boolean functions of n inputs exist? Give the number for n = 2 and n = 4.

A truth table has 2ⁿ rows, each 0 or 1: 2^(2ⁿ) functions. n = 2: 16. n = 4: 65,536.

Design a circuit whose output is 1 when the 4-bit unsigned input ABCD is a multiple of 3. A K-map gives no simplification at all; find a better structure.

Work modulo 3: what is 2 equal to, mod 3?

The multiples (0, 3, 6, 9, 12, 15) are pairwise non-adjacent, so the minimal SOP is six 4-literal minterms. But 2 ≡ −1 (mod 3), so 8A + 4B + 2C + D ≡ −A + B − C + D. With each bit 0 or 1 this sum lies between −2 and 2, so it is a multiple of 3 exactly when it is 0: the number of 1s among B and D equals the number among A and C. That compares two 2-bit counts, a few gates; for wider numbers the same alternating-sum idea extends (and an FSM handles serial input; see the sequential section).

How many select lines does a 32-to-1 multiplexer need? How many 2-to-1 muxes would build it as a tree?

5 select lines. A tree of 2-to-1 muxes needs 16 + 8 + 4 + 2 + 1 = 31.

Build a 3-to-8 decoder from two 2-to-4 decoders with active-high enables and one inverter.

Connect A1 A0 to both decoders' inputs. Enable the first (outputs 0–3) with A2′ (through the inverter) and the second (outputs 4–7) with A2. If the 3-to-8 decoder needs its own enable E, use E·A2′ and E·A2 instead. ()

Estimate, in gate delays, the worst-case delay of a 32-bit ripple-carry adder and of a carry-lookahead adder built as a tree of 4-bit lookahead units.

Ripple: the carry passes through an AND-OR (2 gate delays) per bit, roughly 64 gate delays. Lookahead: a tree of 4-bit units needs ⌈log₄ 32⌉ = 3 levels, and each AND-OR step costs 2 gate delays. The bit generate and propagate signals take 1; group signals rise through the first two levels (4); the top level computes its carries (2); the carries descend two levels (4); the sum XOR adds 1. Total 1 + 4 + 2 + 4 + 1 = 12. The delay grows with the logarithm of the width instead of linearly, at the cost of area and fan-in. ()

What is the difference between a latch and a flip-flop? Where is each used?

A latch is level-sensitive: transparent (output follows input) while its enable is active, holding otherwise. A flip-flop is edge-triggered: it samples its input only at a clock edge. Flip-flops are the default in synchronous design because data cannot race through them; latches appear inside flip-flops, in clock-gating cells, and in some high-performance designs that use time borrowing. ()

Convert a D flip-flop into a T flip-flop and into a JK flip-flop.

T: D = T ⊕ Q. JK: D = J·Q′ + K′·Q.

Bits of a binary number arrive serially, most significant bit first. Design an FSM whose output says whether the number received so far is divisible by 3.

The state is the remainder r ∈ {0, 1, 2}. Appending bit b turns the value v into 2v + b, so r* = (2r + b) mod 3. Transitions: r0: b = 0 → r0, b = 1 → r1; r1: 0 → r2, 1 → r0; r2: 0 → r1, 1 → r2. Output 1 in r0 (Moore). Three states, two flip-flops. ()

How many states does a Mealy machine need to detect the pattern 1101 with overlapping matches? List the transitions.

Four (S0 nothing, S1 "1", S2 "11", S3 "110"). S0: 1 → S1, 0 → S0. S1: 1 → S2, 0 → S0. S2: 1 → S2, 0 → S3. S3: 1 → S1 with output 1 (pattern complete; the trailing 1 is a new prefix), 0 → S0. All other transitions output 0. The Moore version needs a fifth state for "found".

How many flip-flops does a counter need to divide a clock by 1000? How many states does a 5-flip-flop Johnson counter have?

A modulo-1000 counter needs ⌈log₂ 1000⌉ = 10 flip-flops. A Johnson counter with n flip-flops has 2n = 10 states. ()

Design a divide-by-4 clock with a 50% duty cycle, and a divide-by-3 clock with a 50% duty cycle.

Divide by 4: a 2-bit counter's MSB, or two toggle flip-flops in series (each halves the frequency). Divide by 3 at 50%: a mod-3 counter on rising edges produces a signal high for 1 of 3 cycles; a falling-edge flip-flop delays it by half a cycle; ORing the two gives a signal high for 1.5 of 3 cycles. Odd divisors with 50% duty always need both clock edges.

Design a circuit that produces a one-clock-cycle pulse on each rising edge of a synchronous signal x. What changes if x is asynchronous?

Delay x by one flip-flop (x_d) and output x·x_d′. If x is asynchronous, first pass it through a two-flip-flop synchronizer and apply the detector to the synchronized signal, otherwise the AND can see a metastable or inconsistent value.

What is the longest sequence a 3-bit LFSR can produce, and why can it never produce all 8 states?

7 states (2³ − 1). The all-zeros state feeds back XOR(0, 0) = 0 and maps to itself, so a maximal LFSR cycles through all nonzero states and must never enter zero.

Design a serial odd-parity checker: its output is 1 when an odd number of 1s has been received so far.

One flip-flop holding the parity: P* = P ⊕ x, output P, reset to 0. It is a T flip-flop with T = x.

Why is assign clk_out = sel ? clk_b : clk_a; a dangerous way to switch between two clocks, and how does a glitch-free clock multiplexer work?

If sel changes while either clock is high, the output can produce a runt pulse (part of a high phase from one clock followed immediately by the other), which may clock some flip-flops and not others. A glitch-free mux gives each clock an enable flip-flop clocked on that clock's falling edge; each enable can turn on only after the other has turned off (they are cross-coupled through synchronizers), and each clock is ANDed with its enable before the two are ORed. Switching therefore happens only while both clocks are low, and there is a short gap with no clock rather than a glitch.

Compare synchronous and asynchronous resets: one advantage and one risk of each.

Synchronous: reset is ordinary data, so it is timed by STA and filtered of glitches; but it needs a running clock to take effect and adds logic to the D path. Asynchronous: works without a clock and costs no data-path logic; but its release is asynchronous and can cause metastability or flip-flops leaving reset in different cycles, so it must be deasserted through a reset synchronizer. ()

A producer writes bursts of 120 words, one per cycle at 200 MHz, and then stays idle long enough for the FIFO to drain. The consumer reads one word per cycle at 150 MHz continuously. What is the minimum FIFO depth?

A burst lasts 120/200 MHz = 600 ns. In that time the consumer removes 600 ns × 150 MHz = 90 words. The FIFO must absorb the difference: 120 − 90 = 30 words. Real designs add margin for the latency of synchronizing pointers across clock domains (a few entries) and for any consumer stalls.

A vending machine accepts nickels (N) and dimes (D) and dispenses an item at 15 cents without giving change; extra money carries over. How many states, and what are the transitions?

States by credit: 0, 5, 10 cents (three, since 15 or more immediately dispenses). From 0: N → 5, D → 10. From 5: N → 10, D → 0 with dispense (15). From 10: N → 0 with dispense, D → 5 with dispense (20 − 15 = 5 carried). Dispense is a Mealy output on those transitions; a Moore version adds states for "dispensing".

tclk→Q = 70 ps, logic delay 520 ps, tsetup = 40 ps. What is the maximum clock frequency?

Tmin = 70 + 520 + 40 = 630 ps → fmax ≈ 1.59 GHz. ()

A path has tclk→Q,min = 30 ps, a minimum logic delay of 10 ps, and the capture flip-flop's hold time is 55 ps. Is there a problem? Does slowing the clock fix it?

30 + 10 = 40 < 55: a 15 ps hold violation. Slowing the clock does not help, since the period does not appear in the hold check. Insert delay (buffers) on that path or reduce clock skew.

The capture clock arrives 50 ps after the launch clock. How does this skew affect the setup and hold checks?

Setup: the data has 50 ps more time (T + 50 ≥ tcq + tpd + tsu), which helps. Hold: the capture flop holds its sampling window open 50 ps later, so the new data must arrive at least 50 ps later than before (tcq + tcd ≥ th + 50), which hurts. Skew moves margin from one check to the other.

A ring oscillator has 5 inverters, each with a 20 ps delay. What is its frequency? Why must the number of inverters be odd?

A transition must travel around the ring twice per period (once to flip every node, once to flip it back): f = 1/(2·N·tpd) = 1/(2 × 5 × 20 ps) = 5 GHz. With an even number of inversions the ring has a stable state (it is a latch, like cross-coupled inverters) and does not oscillate.

What is metastability, and how much does adding a third flip-flop to a two-flip-flop synchronizer improve its MTBF?

When a flip-flop samples an input that changes within its setup/hold window, its internal loop can balance near the midpoint and take an unbounded time to resolve. The probability of still being unresolved after time t decays as e−t/τ. A third stage adds roughly one more clock period of resolution time, multiplying the MTBF by about eT/τ, an enormous factor (for T = 1 ns and τ = 20 ps, e⁵⁰). The cost is one more cycle of latency.

Why can't an 8-bit counter value be passed to another clock domain by putting a two-flip-flop synchronizer on each bit? Give two correct methods.

Bits that change at the same time may be sampled in different cycles, producing values the counter never held (for example 0111 1111 → 1000 0000 could be read as 1111 1111). Correct methods: convert to Gray code (one bit changes per increment) before synchronizing; or hold the value stable and pass a single handshake signal (request/acknowledge) through synchronizers; or use an asynchronous FIFO for streams of data.

A block of logic takes 1.8 ns, but the design runs at 1 GHz, and its result is only needed every other cycle. How can the design be made to work without pipelining the logic?

Treat it as a multicycle path: make the source registers hold their values for two cycles and the destination register load only every second cycle (with an enable driven by a toggle flip-flop), then tell the timing tool that the path has two cycles for setup (and adjust the hold check accordingly). The logic then has 2 ns, enough for 1.8 ns plus register overheads.

Why do designs use integrated clock-gating cells instead of an AND gate between the clock and an enable?

If the enable changes while the clock is high, an AND gate produces a truncated pulse (a glitch) that may clock some registers and not others. An ICG cell latches the enable while the clock is low, so the AND's enable input is stable whenever the clock is high and only whole pulses pass. Clock gating is still worth doing because it removes the dynamic power of idle registers and their clock wiring. ()

A design fails at high temperature but passes at room temperature, and lowering the clock frequency fixes it. A second design fails at all frequencies but only on some chips. What kind of timing problem does each likely have?

The first is a setup problem: delays grow at high temperature (and low voltage), the critical path no longer fits in the period, and a slower clock gives it the time it needs. The second points to a hold problem (or a clock-domain-crossing bug): hold violations do not depend on frequency, and process variation makes some chips' short paths fast enough, relative to their clock skew, to fail.

What is clock jitter, and how does it enter the setup equation?

Jitter is the variation of each clock edge from its ideal time, from noise in the PLL and clock network. In the worst case two edges arrive closer together than the nominal period, so the setup check uses the shortened period: T − tjitter ≥ tcq + tpd + tsu.

After a rising edge, with a = 1, b = 0, c = 0 beforehand, what are b and c in each block?

always @(posedge clk) begin b <= a; c <= b; end   // block 1
always @(posedge clk) begin b = a;  c = b;  end   // block 2

Block 1 (nonblocking): b = 1, c = 0 (c receives the old b): a shift register. Block 2 (blocking): b = 1, c = 1: c receives the new b. ()

Write a parameterized modulo-N counter that outputs a one-cycle tick when it wraps.

 
module modn #(parameter N = 10, parameter W = $clog2(N)) (
    input  wire         clk, rst,
    output reg  [W-1:0] count,
    output wire         tick
);
    assign tick = (count == N - 1);
    always @(posedge clk)
        if (rst || tick) count <= 0;
        else             count <= count + 1'b1;
endmodule

Using the tick as an enable for slower logic keeps everything on one clock.

What is wrong with always @(a or b) y = a & b & c;?

The sensitivity list omits c, so in simulation y does not update when only c changes, while synthesis ignores the list and builds a 3-input AND: the simulated and synthesized designs disagree. Use always @* (or always_comb), or an assign.

Write a 4-bit register that can load a parallel value, shift left with a serial input, or hold, selected by a 2-bit mode.

 
module shreg4 (
    input  wire       clk, rst, sin,
    input  wire [1:0] mode,          // 00 hold, 01 load, 10 shift left
    input  wire [3:0] d,
    output reg  [3:0] q
);
    always @(posedge clk)
        if (rst) q <= 4'b0000;
        else case (mode)
            2'b01:   q <= d;
            2'b10:   q <= {q[2:0], sin};
            default: q <= q;
        endcase
endmodule

Explain the difference between == and === in Verilog, and why it matters in testbenches.

== is logical equality: if either operand has x or z bits, the result is x (unknown), which an if treats as false. === is case equality: it compares x and z literally and always returns 0 or 1. A testbench that checks if (out == expected) silently passes or fails wrongly when out is x (for example an uninitialized register); !==/=== catch it. Case equality is simulation-only and not synthesizable.

What hardware does this produce?

always @* begin
    count = 0;
    for (i = 0; i < 8; i = i + 1)
        count = count + d[i];
end

The loop is unrolled at synthesis time into a chain (which the tool usually rebalances into a tree) of adders that sums the 8 bits of d: a population counter with a 4-bit result. Loops in synthesizable code describe replicated hardware, not repeated execution over time.

Describe how to implement a 4-requester round-robin arbiter in hardware.

Keep a register with the index of the last granted requester. Mask the request vector so that only requesters after that index remain, and feed it to a priority encoder; if the masked vector is empty, use a second priority encoder on the unmasked requests (wrapping around). Grant the chosen requester (one-hot) and update the pointer. This gives every requester a turn within four grants, unlike a fixed-priority arbiter, which can starve low-priority requesters.

Why do many designers write state machines with a separate clocked block for the state register and a combinational block for the next state, instead of one clocked block?

The two-block style mirrors the hardware (register + next-state logic), makes Mealy outputs and next-state values available combinationally, keeps blocking and nonblocking assignments in their proper places, and makes it easy to see that every state assigns every next-state value (with a default). A single clocked block is fine for Moore machines with registered outputs, but it registers everything assigned inside it, which can add an unintended cycle of latency to outputs.

Find the clock-domain-crossing bug:

// in clock domain B
always @(posedge clk_b) begin
    s1 <= a_valid & a_ready;   // a_valid, a_ready come from domain A
    s2 <= s1;
end

The synchronizer input is combinational logic of two signals from the other domain. The AND can glitch when its inputs change at different times, and the two inputs may be sampled inconsistently, so domain B can see a pulse that never existed in domain A. Compute the AND in domain A, register it there, and synchronize that single registered signal.

Write a module that outputs a pulse one clock cycle wide every N cycles, without using a second clock.

Use a modulo-N counter and output its terminal count, as in the mod-N counter above: assign pulse = (count == N - 1);. Downstream logic uses pulse as a clock enable; generating a divided clock would create a new clock domain with skew and timing complications.

A program runs 5 × 10⁹ instructions with a CPI of 0.8 on a 4 GHz processor. How long does it take?

5 × 10⁹ × 0.8/(4 × 10⁹) = 1.0 s. ()

A 64 KB, 4-way set-associative cache with 64-byte lines serves 48-bit addresses. How many offset, index and tag bits?

Offset log₂ 64 = 6. Sets = 64 KB/(64 × 4) = 256 → index 8. Tag = 48 − 14 = 34. ()

L1 hit time 1 ns, miss rate 5%; L2 hit time 8 ns, local miss rate 30%; DRAM 100 ns. Compute the AMAT.

1 + 0.05 × (8 + 0.3 × 100) = 1 + 0.05 × 38 = 2.9 ns.

Why can summing a large 2-D C array column by column be many times slower than row by row?

C arrays are row-major. Row-by-row access is stride 1: every byte of each 64-byte line fetched is used. Column-by-column access jumps a whole row per element, so each access touches a different line, and for large arrays those lines are evicted before the next column could reuse them: up to one miss per element instead of one per 16 ints. Swap the loops (loop interchange) or tile.

Compare write-through and write-back caches. Which is used for L1 data caches in most CPUs, and why?

Write-through sends every store to the next level (simple, the next level is always current, but heavy traffic); write-back updates only the cache and writes a dirty line back on eviction (much less traffic, needs dirty bits and more complex coherence). Most CPU L1 data caches are write-back (with write-allocate), because repeated stores to the same lines are common and bandwidth to L2 is limited.

In a 5-stage pipeline with forwarding, which data hazard still causes a stall, and why? How does the compiler help?

The load-use hazard: a loaded value exists only at the end of MEM, too late to forward to an instruction that wants it in EX in the next cycle, so one bubble is inserted. Compilers schedule an independent instruction into the slot after the load. ()

Base CPI 1. 20% of instructions are loads, half followed immediately by a dependent instruction (1 stall). 15% are branches, mispredicted 8% of the time with a 12-cycle penalty. What is the CPI?

1 + 0.2 × 0.5 × 1 + 0.15 × 0.08 × 12 = 1 + 0.1 + 0.144 = 1.244. Even an accurate predictor matters when the penalty is long.

Why does a 2-bit saturating counter predict loop branches better than a 1-bit predictor?

A 1-bit predictor flips its prediction after the loop's single exit, so it mispredicts both the exit and the first iteration of the next execution of the loop. A 2-bit counter needs two consecutive mispredictions to change its prediction, so the exit only weakens it and the next run starts with a correct prediction: one miss per loop execution instead of two.

A workload is 70% parallelizable. What speedup do 4 and 16 cores give, and what is the limit?

4 cores: 1/(0.3 + 0.7/4) = 2.11. 16 cores: 1/(0.3 + 0.7/16) = 2.91. Limit: 1/0.3 = 3.33. The serial 30% dominates quickly.

x86-64 uses 48-bit virtual addresses, 4 KB pages and 8-byte page-table entries, with each page-table level occupying exactly one page. How many levels are needed, and how many bits does each level translate?

The page offset is 12 bits, leaving 36 bits of virtual page number. A 4 KB table holds 4096/8 = 512 entries = 9 bits per level. 36/9 = 4 levels of 9 bits. (Five-level paging extends this to 57-bit addresses.)

What is a TLB, and what happens on a TLB miss?

The translation lookaside buffer is a small, highly associative cache of recent virtual-to-physical page translations, so that most memory accesses need no page-table walk. On a miss, hardware (or, on some architectures, software) walks the multi-level page table in memory to find the entry, fills the TLB and retries; if the page is not present in memory, a page fault transfers control to the operating system.

Why does an out-of-order processor need a reorder buffer, if instructions are allowed to execute out of order anyway?

Execution may be out of order, but the architectural state must change in program order, so that an exception or a mispredicted branch leaves the machine exactly as if every earlier instruction completed and no later one did (precise exceptions and recoverable speculation). The reorder buffer holds completed results until all older instructions have completed, then commits them in order, and discards everything younger than a mispredicted branch or a faulting instruction.

How can a C program determine whether the machine is little-endian?

Store a known multi-byte value and inspect its first byte: uint32_t x = 1; bool little = *(uint8_t *)&x == 1;. On a little-endian machine the least significant byte is at the lowest address. (Reading through a uint8_t or unsigned char pointer is allowed by the aliasing rules.) ()

Two threads on different cores each increment their own counter in a loop, but the program runs far slower with two threads than with one. The counters are adjacent elements of an array. What is happening and how is it fixed?

False sharing: both counters share one 64-byte cache line, so each increment needs exclusive ownership of the line, which the coherence protocol takes away from the other core: the line ping-pongs between the cores' caches. Fix by placing each counter in its own line (padding or alignas(64)), or by accumulating in local variables and combining once at the end. ()

A kernel is launched with 128 threads per block. Which global index does thread 5 of block 10 handle? How many blocks cover 10,000 elements?

10 × 128 + 5 = 1285. ⌈10,000/128⌉ = 79 blocks (with a bounds check for the last 112 threads). ()

Within a warp, half the threads take an if branch costing 200 cycles and half take the else branch costing 100 cycles. How long does the warp take? How could the code be restructured?

The warp executes both paths serially: 300 cycles, with half the lanes idle in each. Reorganize the data or the thread-to-work mapping so that the condition is uniform within each warp (for example, sort or partition the work so whole warps take the same branch), or replace the branch with arithmetic when both paths are short.

Shared memory has 32 banks of 4-byte words. Which accesses by the 32 threads of a warp cause bank conflicts: s[tid], s[2*tid], s[32*tid], s[0]?

s[tid]: each thread a different bank, no conflict. s[2*tid]: banks 0, 2, …, 30, each used twice: 2-way conflict (two passes). s[32*tid]: all in bank 0: 32-way conflict. s[0]: all threads read the same word, which is broadcast without conflict.

Why do GPUs devote relatively little area to caches and out-of-order logic, and how do they tolerate memory latency instead?

GPUs optimize throughput rather than single-thread latency. Each SM keeps many warps resident with all their registers on chip, and when one warp waits for memory the scheduler issues instructions from another in the next cycle at no cost. With enough warps in flight, the arithmetic units stay busy despite hundreds of cycles of memory latency, so area goes to ALUs and register files instead of large caches and speculation.

A GPU has 40 TFLOP/s of compute and 1.6 TB/s of memory bandwidth. A kernel performs 4 FLOP per byte loaded. What performance can it reach, and what is the bottleneck?

min(40, 1.6 × 4) = 6.4 TFLOP/s: memory bound. The ridge point is 40/1.6 = 25 FLOP/byte; reaching peak would require improving data reuse (tiling in shared memory, fusing kernels) to raise the intensity.

An SM has 64K 32-bit registers and supports up to 2048 resident threads. A kernel needs 40 registers per thread. How many threads can be resident, and what is the occupancy?

65,536/40 = 1638 threads, rounded down to whole warps (and allocation granularity): about 1632 threads (51 warps) → occupancy ≈ 51/64 ≈ 80%. Reducing to 32 registers per thread would allow 2048 threads (100%).

Explain how tiling matrix multiplication into shared memory reduces global-memory traffic, and by roughly what factor for T × T tiles.

In a naive kernel each thread computing one output element reads a full row of A and column of B from global memory, so every input element is fetched N times. With tiling, a block loads a T × T tile of A and of B into shared memory once, synchronizes, and every thread in the block reuses those values T times. Each global element is therefore loaded N/T times instead of N times: traffic falls by a factor of about T (16 or 32 in practice), raising arithmetic intensity by the same factor.

Many threads atomically increment bins of a 256-bin histogram in global memory, and the kernel is slow. Why, and what is the standard fix?

Atomics to the same address serialize, and popular bins see heavy contention in global memory. Privatize: each block accumulates a histogram in shared memory (fast atomics, contention only within the block), then adds its 256 bins to the global histogram once at the end.

Implement an atomic increment using only compare_exchange_weak in C++, and explain why the loop is needed.

 
#include 

void increment(std::atomic& x)
{
    int old = x.load();
    while (!x.compare_exchange_weak(old, old + 1)) {
        // on failure, old has been updated to the current value; try again
    }
}

Another thread may change x between the load and the compare-and-swap; the CAS then fails (and reloads old), and the loop retries with the fresh value. The weak form may also fail spuriously on some architectures, which the loop handles. This read-modify-write retry pattern is the basis of lock-free algorithms.

What is the difference between a data race and a race condition? Is volatile enough to prevent data races between threads in C++?

A data race is two threads accessing the same memory location concurrently, at least one writing, without synchronization: undefined behavior in C and C++. A race condition is any bug where correctness depends on timing, which can occur even with atomics (for example check-then-act). volatile is not enough: it neither makes operations atomic nor orders them between threads. Use std::atomic, mutexes, or other synchronization.

Draw (in words) the static CMOS implementation of F = (A + B·C)′. How many transistors?

Pull-down (NMOS, implements A + BC): A in parallel with the series pair B–C. Pull-up (PMOS, the dual): A in series with the parallel pair B ∥ C. 6 transistors.

Why are NAND gates generally preferred over NOR gates in CMOS?

A NOR has its PMOS transistors in series. PMOS carriers (holes) are 2 to 3 times slower than electrons, so series PMOS stacks must be made very wide to match drive strength, giving more area and input capacitance (logical effort 5/3 for NOR2 versus 4/3 for NAND2). A NAND puts the series stack in the faster NMOS. High fan-in NORs are especially slow.

A driver has VOH = 2.4 V and VOL = 0.4 V; a receiver has VIH = 2.0 V and VIL = 0.8 V. What are the noise margins? Would a receiver with VIH = 3.5 V work?

NMH = 2.4 − 2.0 = 0.4 V; NML = 0.8 − 0.4 = 0.4 V. With VIH = 3.5 V, NMH = −1.1 V: no, a high output can fall in the receiver's undefined region; a level shifter is needed. ()

Design a non-inverting amplifier with a gain of 11, and an inverting amplifier with a gain of −5 and an input resistance of 10 kΩ.

A minimum inverter must drive a load equal to 256 times its own input capacitance. How many inverter stages minimize the delay, and roughly how much faster is that than driving the load directly?

Write an expression that is true exactly when an unsigned x is a power of two.

x != 0 && (x & (x - 1)) == 0. Subtracting 1 flips the lowest set bit and every bit below it, so the AND clears the lowest set bit; the result is 0 only if there was just one.

Isolate the lowest set bit of x, and clear it.

Isolate: x & -x (for unsigned x, −x = ~x + 1, which keeps only the lowest 1). Clear: x & (x - 1). For x = 0b10110: x & −x = 0b00010; x & (x − 1) = 0b10100.

Reverse the bits of a byte without a loop.

 
uint8_t rev8(uint8_t x)
{
    x = (uint8_t)(((x & 0xF0) >> 4) | ((x & 0x0F) << 4));   // swap nibbles
    x = (uint8_t)(((x & 0xCC) >> 2) | ((x & 0x33) << 2));   // swap pairs
    x = (uint8_t)(((x & 0xAA) >> 1) | ((x & 0x55) << 1));   // swap neighbors
    return x;
}

Each step swaps groups of half the previous size: log₂ 8 = 3 steps. A 256-entry lookup table is the other common answer.

What does the volatile qualifier do, and give two situations in embedded code that require it.

It tells the compiler that the object can change, or that accessing it has effects, outside the code it can see, so every read and write in the source must actually be performed, in order, and not cached in registers or removed. Required for memory-mapped hardware registers and for variables shared between an ISR and the main program. It does not make accesses atomic. ()

Give three different meanings of the keyword static in C.

(1) A local variable declared static keeps its value between calls (static storage duration, initialized once). (2) A global variable or function declared static has internal linkage: visible only within its source file. (3) In an array parameter, int a[static 10] promises at least 10 elements (C99). (In C++ it additionally marks class members shared by all instances.)

A circular buffer has N = 64 entries. Write the index update without a division or a branch, and explain why N should be a power of two.

head = (head + 1) & (N - 1);. For N = 2ᵏ, masking with N − 1 keeps the low k bits, which equals (head + 1) mod N. For other sizes the mask does not compute the modulus, and a % (a division) or a compare-and-reset is needed.

Every element of an array appears twice except one. Find it in O(n) time and O(1) memory.

XOR all elements: pairs cancel (a ⊕ a = 0) and XOR is associative and commutative, so the result is the unpaired element. The same identity underlies parity and RAID-5 reconstruction.

With uint8_t a = 200, b = 100;, what are a + b > 255 and (uint8_t)(a + b) > 255? Why?

a + b is computed as an int after promotion, 300, so the first comparison is true. Casting to uint8_t gives 44 before the comparison, so the second is false. Integer promotion means small types never overflow inside an expression; truncation happens only when the result is stored or cast.

Design a hardware debouncer for a push button sampled by a 1 MHz clock, accepting a new level only after it has been stable for 5 ms.

Synchronize the button with two flip-flops. Keep the current debounced output in a register and a 13-bit counter (5 ms × 1 MHz = 5000 < 2¹³). Each clock: if the synchronized input equals the debounced output, clear the counter; otherwise increment it, and when it reaches 4999, copy the input to the output and clear the counter. Any bounce resets the count, so the output changes only after 5 ms of a stable new level. An edge detector on the output gives a one-cycle "pressed" pulse. ()

A synchronous FIFO has 8 entries, addressed by a write pointer and a read pointer. When both pointers are equal the FIFO could be empty or full. How do designers tell the two apart without a separate counter?

Make each pointer one bit wider than the address: 4 bits for 8 entries. The low 3 bits address the memory; the extra bit flips every time a pointer wraps around. Empty: all 4 bits equal (the reader has caught up with the writer on the same lap). Full: the low 3 bits equal and the top bits different (the writer is exactly one lap ahead, so write − read = 8). In an asynchronous FIFO the pointers are Gray-coded before crossing clock domains, and the full test becomes: the top two bits differ and the rest are equal. ()

How would you verify a FIFO design? List the checking mechanisms and the scenarios you would make sure to cover.

Checking: a reference model (a simple queue in the testbench) and a scoreboard that compares every word read with the model's next word; assertions that a write when full and a read when empty are refused (or flagged), that the occupancy never exceeds the depth, and that the flags agree with the model. Stimulus: directed tests for reset, filling to full, draining to empty and the error cases, then constrained-random tests with random write and read patterns over long runs. Coverage, to know when to stop: full and empty both reached, simultaneous read and write while empty, full and in between, every pointer wrapping around, back-to-back full/empty transitions. For an asynchronous FIFO, add many clock-frequency ratios and phase relationships and a CDC analysis tool, because simulation alone does not model metastability. ()

What is the difference between code coverage and functional coverage? Is 100% code coverage enough?

Code coverage is measured automatically from the RTL: which lines, branches, expressions, signal toggles and FSM states and transitions were exercised. Functional coverage is written by the verification engineer from the specification: which features, scenarios and combinations of conditions occurred (for example, "a burst write while the FIFO is one entry from full"). 100% code coverage is not enough: it cannot reveal functionality that is missing from the code, and it does not show that important combinations of conditions occurred together, or that the outputs were checked.

Every request must be granted within 1 to 4 cycles. Write this as a SystemVerilog assertion and explain each part.

 
assert property (@(posedge clk) disable iff (rst)
                 req |-> ##[1:4] gnt)
    else $error("req not granted within 4 cycles");

@(posedge clk) samples the signals at each rising edge. disable iff (rst) turns the check off during reset. req |-> is an implication: the property is checked starting at every edge where req is 1, and passes trivially elsewhere. ##[1:4] gnt requires gnt to be 1 at some edge 1 to 4 cycles later. The same property can be simulated as a checker or proved for all possible inputs by a formal tool.

What does the stuck-at fault model assume, and what must a test pattern do to detect a stuck-at-0 fault on an internal node? How does scan help?

It models a manufacturing defect as one node permanently fixed at 0 or 1. To detect stuck-at-0 on node n, a pattern must excite the fault (set the inputs so that a good circuit drives n to 1) and propagate the difference to an observable output (set the other gates along a path so that the output depends on n). Deep inside sequential logic both are hard, because the inputs and outputs of internal logic are flip-flops. Scan chains let the tester load every flip-flop directly and read every flip-flop back, so each block of combinational logic between flip-flops can be tested as if its inputs and outputs were pins; ATPG tools then generate patterns covering typically more than 99% of stuck-at faults. ()

A die of 6 cm² is made in a process with 0.1 defects per cm². Using the Poisson model, what fraction of dies are free of defects? Why do very large GPUs ship with some of their SMs disabled?

Y = e−D·A = e−0.6 ≈ 55%. Almost half the dies contain at least one defect, and most defects land in the large replicated arrays of SMs and cache. Designing the product with fewer active units than the die contains (for example 132 of 144 SMs) lets a die with defects in a few SMs be sold after those SMs are fused off, which raises the effective yield far above 55%. Dies are also binned by how many units work and how fast they run, into different products. ()

A chip draws 200 W at 0.8 V. What current flows, and what total resistance can the power-delivery network have if the IR drop must stay below 2% of the supply?

I = 200/0.8 = 250 A. 2% of 0.8 V is 16 mV, so R ≤ 16 mV/250 A = 64 μΩ, the reason a large chip uses thousands of power and ground bumps in parallel, thick upper metal layers, and voltage regulators placed close to the package. Why does lowering the supply voltage together with the clock frequency (DVFS) save much more energy than lowering the frequency alone?

Dynamic power is αCV²f, and the energy per operation is αCV², independent of frequency. Lowering only f lowers the power, but the task takes proportionally longer, so the energy to finish it stays about the same (and leakage energy grows, because the chip is on longer). Lowering V reduces the energy per operation quadratically. Voltage cannot drop alone, because gates slow down at lower voltage, so the frequency must drop with it: DVFS pairs each frequency with the lowest voltage that still meets timing. ()

A design that reaches 2 GHz as an ASIC runs at only 300–500 MHz on an FPGA. Why? Why are FPGAs still used in chip development?

In an FPGA, logic is built from lookup tables and connected through programmable routing, chains of multiplexers and switches whose resistance and capacitance add delay at every hop; routing typically dominates the delay, and a function that is one optimized cell in an ASIC becomes one or more LUTs plus routing. FPGAs are still used because they can be reprogrammed in minutes: whole chips are prototyped or emulated on large FPGA systems before tapeout to run real software and find bugs months before silicon exists, and FPGAs ship in products whose volume does not justify an ASIC. ()

What does clock-tree synthesis do, and why does the clock network matter so much for power?

It builds a network of buffers and wires (trees, H-trees or meshes) that distributes the clock from its source to every flip-flop with nearly equal arrival times (low skew) and sharp transitions, within the timing budget. The clock is the only signal that switches twice every cycle (activity factor 1) and it drives the clock pins of every flip-flop, so the clock network can account for a third or more of a chip's dynamic power, which is why clock gating is used so widely. ()

A chip passes all its tests, but in the system it fails occasionally, only when a neighboring high-power block switches from idle to full activity. What are the likely causes, and how would you investigate?

The symptom points to supply noise: the sudden current step causes a voltage droop (IR drop plus L·di/dt) that slows the gates of the failing block until a critical path misses setup. Crosstalk from switching neighbors and temperature gradients are other candidates. To investigate: reproduce with controlled workloads; check whether the failure disappears at a lower frequency or a higher supply voltage (a strong sign of a timing margin problem); measure the supply with on-die droop detectors or monitors; and compare with power-integrity simulation of that scenario. Fixes include more decoupling capacitance, slowing down the ramp of the aggressor block (staggered wake-up), adaptive clocking that stretches the clock during droops, or more timing margin on the affected paths.
