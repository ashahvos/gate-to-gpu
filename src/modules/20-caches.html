A modern core can execute several instructions per nanosecond, but a read from DRAM takes 60 to 100 nanoseconds: hundreds of cycles. If every load went to main memory, the processor would spend almost all its time waiting. Caches, small fast memories that keep copies of recently used data close to the processor, close most of that gap, and their behavior largely determines the performance of real programs.

The memory hierarchy

Fast memory is small and expensive; large memory is slow and cheap. No single technology offers both, so systems stack several levels, each a copy of part of the level below it.

Typical sizes and latencies for a current desktop or server processor. The upper levels are SRAM on the processor die; main memory is DRAM ().

The hierarchy works because programs exhibit locality:

  • Temporal locality: data used recently is likely to be used again soon (loop counters, a function's local variables, the instructions of a loop body).
  • Spatial locality: data near recently used data is likely to be used soon (the next array element, the next instruction).

A cache exploits temporal locality by keeping what was recently accessed, and spatial locality by moving data in blocks (also called lines), typically 64 bytes: a miss on one byte brings in its whole neighborhood. Caches are managed entirely by hardware and are invisible to the program's correctness, unlike registers, which the compiler manages explicitly.

Finding data in a cache: tag, index and offset

A cache must answer, for every address, "is this block here, and where?" in about a nanosecond. The address is split into three fields:

  • The offset selects a byte within the block: log₂(block size) bits.
  • The index selects which set of the cache the block can live in: log₂(number of sets) bits.
  • The tag is the rest of the address. It is stored alongside the block and compared on every access to confirm that the block in that set is the one requested.

Each line also has a valid bit (does it hold anything?) and, in write-back caches, a dirty bit (has it been modified?).

A 16 KB direct-mapped cache with 64-byte blocks has 256 lines: 6 offset bits, 8 index bits and an 18-bit tag for a 32-bit address. A hit requires the line to be valid and its stored tag to match.

For the cache above, the address 0x12345678 has offset = the low 6 bits = 0x38 (byte 56 of the block), index = bits 13 to 6 = 0x59 (line 89), and tag = bits 31 to 14 = 0x48D1. An access hits if line 89 is valid and holds tag 0x48D1. Every address whose bits 13 to 6 are 0x59 competes for that one line.

Associativity

In a direct-mapped cache each block has exactly one possible location. That makes lookup fast and simple (one tag comparison), but two frequently used blocks that share an index evict each other repeatedly, even if the rest of the cache is empty.

An N-way set-associative cache groups lines into sets of N; a block can go in any of the N ways of its set. A lookup reads all N tags of the set in parallel and compares them simultaneously, using N comparators and an N-to-1 multiplexer for the data. A fully associative cache is a single set: any block can go anywhere, at the cost of comparing against every tag. For a cache of capacity C, block size B and associativity N, the number of sets is C/(B·N). Typical L1 caches are 8- to 12-way, and larger caches 16-way or more.

When a set is full, a replacement policy picks the victim. Least recently used (LRU) works well but is costly to track exactly beyond a few ways, so hardware uses approximations (pseudo-LRU trees) or even random replacement for large caches.

Writes

  • Write-through: every write updates both the cache and the next level. Simple and always consistent, but it generates a lot of traffic, so it is paired with a write buffer that absorbs bursts.
  • Write-back: writes update only the cache and set the line's dirty bit; the block is written to the next level only when it is evicted. Much less traffic when data is written repeatedly; this is what most caches above main memory use.
  • On a write miss, write-allocate brings the block into the cache and then writes it (natural with write-back); no-write-allocate writes straight to the next level.

Why misses happen

  • Compulsory (cold) misses: the first access to a block. Larger blocks and prefetching reduce them.
  • Capacity misses: the program's working set is larger than the cache. Only a larger cache, or a program that reuses data in smaller pieces, helps.
  • Conflict misses: too many active blocks map to the same set. More associativity reduces them.
  • In multiprocessors, coherence misses occur when another core's write invalidates a cached copy ().

Average memory access time

Cache performance is summarized by the average memory access time:

AMAT = hit time + miss rate × miss penalty

With several levels, the miss penalty of one level is the AMAT of the next: AMAT = tL1 + mL1·(tL2 + mL2·tmem), where mL2 is the local miss rate of L2 (misses per access that reaches L2). With tL1 = 1 ns, mL1 = 10%, tL2 = 5 ns, mL2 = 20% and tmem = 100 ns, AMAT = 1 + 0.1 × (5 + 0.2 × 100) = 3.5 ns. Without L2 it would be 1 + 0.1 × 100 = 11 ns.

In processor terms, misses add stall cycles: CPI = CPIbase + (memory accesses per instruction) × (miss rate) × (miss penalty in cycles). A miss penalty of 200 cycles with a 1% miss rate on 0.3 data accesses per instruction adds 0.6 to the CPI, which is why out-of-order processors try so hard to keep working while misses are outstanding ().

Writing cache-friendly code

The same algorithm can run several times faster or slower depending on its memory access pattern. C stores two-dimensional arrays in row-major order: a[r][0], a[r][1], … are consecutive in memory.

Traversing along rows uses every byte of each fetched cache line; traversing down columns jumps a whole row per access. 
// Good: the inner loop walks consecutive addresses (stride 1)
for (int r = 0; r < N; r++)
    for (int c = 0; c < N; c++)
        sum += a[r][c];

// Bad for large N: the inner loop jumps N * sizeof(int) bytes per access
for (int c = 0; c < N; c++)
    for (int r = 0; r < N; r++)
        sum += a[r][c];   //!

With 4-byte ints and 64-byte lines, the first loop misses once per 16 elements. In the second, if N is large enough that a column's worth of lines does not fit in the cache, every access misses: 16 times more misses for identical arithmetic. Other standard techniques:

  • Loop interchange reorders nested loops so the innermost loop has stride 1.
  • Blocking (tiling) splits a large computation, such as matrix multiplication, into sub-blocks small enough to stay in the cache while they are reused, turning capacity misses into hits. GPU programs do the same with on-chip shared memory ().
  • Structure of arrays instead of array of structures, when a loop uses only one field: the loop then streams through one dense array instead of skipping over the unused fields.
  • Keep hot data compact and aligned, and avoid pointer-chasing structures (linked lists) in performance-critical loops: each node may be a separate miss.

Virtual memory

Programs do not use physical addresses directly. Each process sees its own virtual address space, which the hardware translates to physical addresses using tables maintained by the operating system. This isolates processes from each other, lets each program be linked as if it owned the whole address space, enforces permissions (read, write, execute, kernel-only), and lets the OS keep only the actively used parts of a program in DRAM.

Translation works in units of pages, typically 4 KB. The low 12 bits of an address (the page offset) are unchanged; the upper bits, the virtual page number, are mapped through a page table to a physical page number. Because a flat table for a 48-bit address space would be enormous, page tables are trees of several levels, and walking them takes several memory accesses. To avoid that on every access, the processor caches recent translations in a translation lookaside buffer (TLB), a small, highly associative cache of page table entries.

Translation through the TLB. A TLB miss triggers a page table walk; if the page is not in memory at all, a page fault transfers control to the operating system, which loads it from storage.

Translation and caching interact. Many L1 caches are virtually indexed, physically tagged: the index bits are taken from the page offset, which needs no translation, so the cache lookup starts in parallel with the TLB lookup. That works only if the cache's size divided by its associativity is at most the page size, one reason L1 caches are typically 32 to 48 KB with 8 to 12 ways.

Summary

  • Locality (temporal and spatial) lets small fast caches serve most accesses; data moves in 64-byte blocks.
  • Address = tag | index | offset. Offset bits = log₂ B; sets = C/(B·N); index bits = log₂ sets.
  • Direct-mapped is fast but suffers conflict misses; N-way set-associative compares N tags in parallel; replacement is LRU or an approximation.
  • Write-back + write-allocate is the norm; write-through needs a write buffer.
  • Misses: compulsory, capacity, conflict (+ coherence). AMAT = hit time + miss rate × miss penalty, applied level by level.
  • Stride-1 access, loop interchange, blocking and compact layouts make code cache-friendly.
  • Virtual memory translates pages through page tables; the TLB caches translations.

A 32 KB direct-mapped cache has 64-byte blocks and 32-bit addresses. How many offset, index and tag bits are there?

Offset: log₂ 64 = 6. Lines: 32 KB/64 B = 512 → index 9. Tag: 32 − 9 − 6 = 17.

A cache has a 1 ns hit time, a 5% miss rate and an 80 ns miss penalty. What is the AMAT?

1 + 0.05 × 80 = 5 ns.

Repeat the address split for a 32 KB, 4-way set-associative cache with 64-byte blocks and 32-bit addresses.

Sets = 32 KB/(64 × 4) = 128 → index 7 bits; offset 6; tag 32 − 13 = 19. Higher associativity means fewer sets, so fewer index bits and more tag bits.

Classify each miss as compulsory, capacity or conflict: (a) the first time a program touches an array; (b) a loop over a 1 MB array, repeated, with a 256 KB cache; (c) two small arrays whose addresses differ by exactly the cache size, accessed alternately in a direct-mapped cache.

(a) compulsory; (b) capacity: the working set does not fit no matter how it is placed; (c) conflict: they map to the same lines and evict each other although the cache is mostly empty.

Why do caches transfer 64-byte blocks instead of just the bytes requested?

To exploit spatial locality: neighboring data is likely to be needed soon, and DRAM delivers a burst of consecutive bytes for little more than the cost of the first one. Larger blocks reduce compulsory misses and amortize the per-access overhead, but blocks that are too large waste bandwidth and cache space on unused bytes and increase conflict misses.

A direct-mapped cache has 4 lines of 4 bytes. Trace the byte addresses 0x00, 0x04, 0x10, 0x00, 0x14, 0x04, 0x10, giving hit or miss for each. Then repeat with a 2-way set-associative cache of the same total size (2 sets, LRU).

Direct-mapped, index = (address >> 2) mod 4: 0x00 → line 0 miss; 0x04 → line 1 miss; 0x10 → line 0 miss (evicts 0x00); 0x00 → miss (evicts 0x10); 0x14 → line 1 miss (evicts 0x04); 0x04 → miss; 0x10 → miss. 7 misses.

2-way, set = (address >> 2) mod 2: 0x00 → set 0 miss; 0x04 → set 1 miss; 0x10 → set 0 miss (both fit); 0x00 → hit; 0x14 → set 1 miss; 0x04 → hit; 0x10 → hit. 4 misses, 3 hits: the extra way removed the conflict misses.

L1: 1 ns hit, 8% miss rate. L2: 6 ns hit, 25% local miss rate. Memory: 90 ns. Compute the AMAT with and without the L2, and the global L2 miss rate.

With L2: 1 + 0.08 × (6 + 0.25 × 90) = 1 + 0.08 × 28.5 = 3.28 ns. Without: 1 + 0.08 × 90 = 8.2 ns. Global L2 miss rate (fraction of all accesses that go to memory): 0.08 × 0.25 = 2%.

A processor has a base CPI of 1.0. Each instruction makes one instruction fetch and, on average, 0.3 data accesses. The instruction cache misses 2% of fetches and the data cache 5% of accesses; each miss costs 100 cycles. What is the effective CPI?

CPI = 1 + 1 × 0.02 × 100 + 0.3 × 0.05 × 100 = 1 + 2 + 1.5 = 4.5. Memory stalls make this processor four and a half times slower than its ideal, which is why miss rates of a few percent matter so much.

A 1024 × 1024 array of 4-byte ints is summed with a cache of 32 KB and 64-byte lines. Estimate the number of cache misses for row-order and for column-order traversal.

Row order: one miss per 16 ints: 2²⁰/16 = 65,536 misses. Column order: walking down one column touches 1024 different lines (one per row), 64 KB of lines, more than the 32 KB cache, so the lines are evicted before the next column could reuse them: essentially every access misses, about 1,048,576 misses, 16 times more.

A loop writes 1000 times to the same 4-byte variable. How much traffic reaches the next memory level with a write-through cache and with a write-back cache?

Write-through: every write is forwarded: 1000 writes (4 KB of traffic, possibly merged by a write buffer). Write-back: the line is marked dirty and written back once, when it is eventually evicted: one 64-byte block write.

A system has 32-bit virtual addresses and 4 KB pages, with 4-byte page table entries. How large is a single-level page table for one process? Why do real systems use multi-level tables?

The VPN has 32 − 12 = 20 bits: 2²⁰ entries × 4 B = 4 MB per process, mostly describing unused address space. A two-level table allocates second-level tables only for regions in use, so a small process needs a few kilobytes. For 48-bit addresses the flat table would be 512 GB, so four or five levels are used.

For blocked (tiled) multiplication of double-precision matrices, three B × B tiles (one each of A, B and C) should fit in a 32 KB L1 cache. What is the largest power-of-two tile size B? Why does tiling reduce misses?

3 × 8 bytes × B² ≤ 32,768 → B² ≤ 1365 → B ≤ 36, so B = 32 (24 KB, leaving room for other data). Without tiling, each element of B is loaded once per row of A, and for large matrices it has been evicted by the time it is needed again (capacity misses). With tiles that stay resident, each loaded element is reused B times before eviction, cutting memory traffic by roughly a factor of B.

An L1 cache is virtually indexed and physically tagged with 4 KB pages. Why must cache size/associativity be at most 4 KB? Give two cache configurations that satisfy this for a 48 KB cache and a 32 KB cache.

The index and offset bits must lie within the 12-bit page offset, which is the same in virtual and physical addresses, so the set can be selected before translation finishes. Bytes per way = size/associativity must be ≤ 4 KB (2¹² bytes). 48 KB → 12-way (4 KB per way); 32 KB → 8-way. This is why L1 associativity grows when L1 capacity grows.

A TLB has 64 entries. What is its reach (the memory it can map without misses) with 4 KB pages and with 2 MB pages? Why do large-memory applications such as databases and GPU drivers use huge pages?

4 KB pages: 64 × 4 KB = 256 KB. 2 MB pages: 64 × 2 MB = 128 MB. A program touching gigabytes of data with 4 KB pages takes TLB misses constantly, each costing a page table walk of several memory accesses; huge pages extend the reach by 512 times and also shorten the walks.
